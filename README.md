## Решения

Подробные объяснения — в docstring модулей, здесь только главное.

**Факториал.** `reduce(operator.mul, range(2, n + 1), 1)`. Начальное значение 1 — это
произведение пустого набора чисел, поэтому 0! и 1! получаются без отдельной ветки.
Без начального значения `reduce` на пустом диапазоне бросил бы `TypeError`.

**Генератор простых.** Бесконечный: сколько чисел взять, решает вызывающий код
(`islice`, `takewhile`). Алгоритм — решето Эратосфена без верхней границы: для
каждого простого p хранится только его ближайшее непройденное кратное, и
вычёркивание начинается с p². Поэтому в памяти только простые до √n, а простые для
вычёркивания даёт второй, отстающий экземпляр того же генератора.

**Несколько функций через `map`.** Формулировка допускает три трактовки; выбрана
«каждая функция к каждому элементу»: элементу `x` соответствует кортеж
`(f1(x), f2(x), …)`, внешний `map` идёт по элементам, внутренний — по функциям.
«Каждая функция ко всему списку» не требует поэлементного `map`, а «функции по
цепочке» — это конвейер из повышенного задания №9. Результат ленивый; функции
собираются в кортеж, потому что обходятся для каждого элемента.

**Класс-итератор.** `PrimeIterator` — тот же алгоритм, что у генератора, записанный
через `__iter__`/`__next__`. Повтор алгоритма сознательный: сравнение показывает, что
делает `yield`. Генератор сам помнит локальные переменные и место остановки, а класс
хранит это в атрибутах и по ним понимает, откуда продолжить. Отстающий итератор
создаётся при первой надобности, а не в `__init__` — иначе каждый итератор создавал
бы следующий, и конструктор упал бы с `RecursionError`; генератору эта ленивость
достаётся даром.

**Конвейер.** Шаг — функция «поток → поток», `pipeline(*steps)` соединяет шаги через
`reduce` и возвращает новую функцию. Готовые шаги `keep`, `transform`, `take` —
обёртки над `filter`, `map`, `islice`, поэтому промежуточных списков нет: каждый
элемент проходит все шаги до того, как взят следующий. Шаги проверяются при сборке,
результат шага — при запуске, с номером шага в сообщении. Конвейер сам является
шагом и может входить в другой конвейер.

**Проверка аргументов** одна на весь пакет ([`checks.py`](funclab/checks.py)): не тот
тип — `TypeError`, недопустимое значение — `ValueError`, `bool` числом не считается.

## Ограничения

- `factorial` перемножает числа по одному, поэтому в разы медленнее
  `math.factorial`, который умножает попарно; разрыв растёт с n.
- `primes()` и `PrimeIterator` бесконечны и `StopIteration` не бросают; без
  `islice`/`takewhile` цикл по ним не закончится.
- Шаг конвейера, которому нужен весь поток (например, `sorted`), читает его сразу
  при запуске и на бесконечном входе не завершится.
- Ошибка внутри функции пользователя в `map_all` или конвейере появляется не при
  вызове, а когда очередь доходит до этого элемента: вычисления ленивые.
